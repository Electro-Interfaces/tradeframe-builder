# Система учёта ГСМ

> ⚠️ Документ требует ревизии перед использованием как технического источника. Внутри есть устаревшие упоминания Supabase; текущая рабочая схема проекта — backend-first через Express и PostgreSQL.

## Назначение

Модуль учёта ГСМ в рамках платформы TradeControl — единая система контроля движения топлива на сети АЗС. Охватывает полный цикл: от приёмки топлива до продажи клиенту, с автоматическим выявлением расхождений.

Система организует четыре контура учёта, каждый из которых решает свою задачу, но работает на общих данных.

---

## Четыре контура учёта

### 1. Технологический учёт

**Задача:** отвечать на вопрос «сколько топлива физически есть и куда оно делось».

Данные поступают автоматически с оборудования АЗС:
- **Резервуары** — уровень, объём, масса, температура, плотность, уровень воды (датчики, каждые 5-10 минут)
- **ТРК** — показания счётчиков при каждой операции отпуска
- **Приёмка** — фактические замеры при сливе из бензовоза (объём, масса, плотность, температура)

На этом уровне считаем:
- Фактические остатки в каждом резервуаре
- Объём отпуска по каждой ТРК за смену
- Факт поступления при каждой поставке
- **Потери** — разница между расчётным остатком (было + пришло − продано) и фактическим замером. Потери возникают из-за испарения, температурного расширения/сжатия, погрешности датчиков, технологических утечек

Нормативы потерь регламентированы приказом Минэнерго №527 и ГОСТ Р 8.595-2004.

### 2. Управленческий учёт

**Задача:** давать информацию для принятия решений — что заказывать, когда, выгодно ли продаём.

Строится на данных технологического учёта плюс коммерческая информация:
- **Маржа** по каждому виду топлива = цена продажи − закупочная цена
- **Оборачиваемость** ёмкости — как быстро продаётся содержимое резервуара
- **Прогноз точки заказа** — когда остаток достигнет минимума и нужна новая поставка
- **Потери в рублях** — во сколько обходятся расхождения технологического учёта
- **KPI по станциям** — объём продаж, средний чек, доля безналичных платежей

### 3. Бухгалтерский учёт

**Задача:** вести учёт по правилам ПБУ/ФСБУ для официальной отчётности.

Переводит операции с топливом в бухгалтерские проводки:
- **Оприходование** ГСМ при поступлении → Дт 41 «Товары» Кт 60 «Поставщики»
- **Реализация** при продаже → Дт 62/50/51 Кт 90 «Продажи»
- **Себестоимость** списание → Дт 90.2 Кт 41 (метод FIFO или средневзвешенная)
- **Потери в пределах норм** → Дт 44 «Расходы на продажу» Кт 41
- **Потери сверх норм** → Дт 94 «Недостачи» Кт 41
- **Инвентаризация** — формирование сличительных ведомостей (ИНВ-3)

Данные выгружаются в 1C:Бухгалтерия.

### 4. Налоговый учёт

**Задача:** корректно рассчитать налоговую базу и подготовить данные для отчётности в ФНС.

- **НДС** — входящий (по ТТН от поставщика) и исходящий (по продажам через ККТ)
- **Нормативные потери** — уменьшают налоговую базу по налогу на прибыль (НК РФ ст. 254 п.7), но только в пределах утверждённых норм
- **Сверхнормативные потери** — не уменьшают налоговую базу, списываются за счёт прибыли
- Данные для книги покупок и книги продаж

## Как контуры связаны между собой

```
Оборудование АЗС
(датчики, ТРК, ККТ)
       │
       ▼
┌─────────────────────┐
│ ТЕХНОЛОГИЧЕСКИЙ     │  Физика: что измерено датчиками
│ Остатки, отпуск,    │  и зафиксировано при приёмке
│ поступления, потери  │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ УПРАВЛЕНЧЕСКИЙ      │  Деньги: маржа, прогнозы,
│ Маржа, KPI,         │  решения по заказам
│ прогнозы, аналитика │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ БУХГАЛТЕРСКИЙ       │  Проводки: оприходование,
│ Проводки, 1C,       │  реализация, списание
│ инвентаризация      │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ НАЛОГОВЫЙ           │  Отчётность: НДС, нормативные
│ НДС, потери по      │  потери, налоговая база
│ нормам, декларации   │
└─────────────────────┘
```

Ключевой принцип: **каждый следующий контур строится на данных предыдущего**. Технологический учёт — фундамент. Если он неточен — всё остальное будет с ошибками.

## Автоматическая сверка

Система регулярно сравнивает данные между контурами и выявляет расхождения:

| Что сверяем | Источник А | Источник Б | Допуск |
|------------|-----------|-----------|--------|
| Остатки | Датчики резервуара | Расчёт (было + пришло − продано) | 0.5% |
| Отпуск | Счётчики ТРК | Кассовые операции (ККТ) | 0.1% |
| Поступления | Факт приёмки | Документы поставщика (ТТН) | 0.5% |
| Выручка | ККТ (фискальные данные) | Банк (эквайринг + инкассация) | 0 ₽ |

При превышении допуска формируется оповещение ответственному.

## Движение топлива (полный цикл)

```
Поставщик → ТТН → Приёмка на АЗС → Резервуар → ТРК → Клиент → ККТ
   │           │         │              │          │              │
   │           │         │              │          │              │
   Закупка   Документ  Факт замера   Хранение   Отпуск       Оплата
   цена      объём/    объём/масса   остатки    литры        сумма
             масса     плотность     потери     стоимость    способ
```

На каждом этапе фиксируются данные, которые потом используются во всех четырёх контурах учёта.

## Источники данных

| Источник | Что даёт | Протокол |
|----------|---------|----------|
| STS API (pos.autooplata.ru) | Резервуары, ТРК, смены, транзакции, поступления | REST API |
| ККТ (фискальный регистратор) | Фискальные чеки, суммы наличных/безнала | Через STS |
| TradeCorp | Корпоративные операции (топливные карты) | REST API |
| MSTO | Онлайн-заказы (мобильные платежи) | REST API |
| Supabase | Справочники (сети, станции, пользователи, пороги) | REST API |
| 1C:Бухгалтерия | Бухгалтерские данные (импорт/экспорт) | XML |

---

## Роли и доступ

| Роль | Контуры | Что видит |
|------|---------|-----------|
| Оператор АЗС | Технологический | Остатки своей станции, приёмка, смена |
| Территориальный менеджер | Технологический + Управленческий | Все станции региона, KPI, потери |
| Руководитель сети | Все четыре | Полная аналитика по сети, маржа, сверка |
| Бухгалтер | Бухгалтерский + Налоговый | Проводки, инвентаризация, выгрузка в 1C |

## Текущее состояние в TradeControl

Что уже работает:
- Отображение остатков резервуаров в реальном времени
- Транзакции продаж с разбивкой по видам топлива и способам оплаты
- Поступления по ТТН (документальные и фактические данные)
- Сменные отчёты с полной детализацией
- Книжные остатки (расчёт: было + пришло − продано)
- Сверка корпоративных операций (TradeCorp и MSTO)
- Экспорт в 1C XML
- Калибровочные таблицы резервуаров

Что нужно реализовать:
- Расчёт и отображение потерь (нормативных и фактических)
- Закупочные цены и расчёт маржи
- Маппинг операций в бухгалтерские проводки
- Расширенная сверка между всеми контурами
- Налоговые нормативы потерь
- Дашборд управленца с KPI
