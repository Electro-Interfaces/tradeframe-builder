# YouTrack - Настройка и правила работы

## Общая информация

- **URL:** https://mag.youtrack.cloud/
- **API:** MCP + REST API (для расширенных операций)
- **MCP:** Официальный YouTrack Remote MCP (JetBrains, HTTP transport)
- **REST API:** `https://mag.youtrack.cloud/api` (Bearer token auth)
- **Язык:** Русский (все описания, комментарии, коммиты)

## 🚀 Быстрый старт: Подключение YouTrack к Claude Code

### Предварительные требования

- **Claude Code** установлен и настроен
- Аккаунт в YouTrack с доступом к проекту

### Шаг 1: Получение токена YouTrack

1. Откройте YouTrack: https://mag.youtrack.cloud/

2. Войдите в свой аккаунт

3. Нажмите на аватар в правом верхнем углу → **Profile**

4. Перейдите в раздел **Account Security** → **Tokens**

   Или прямая ссылка: `https://mag.youtrack.cloud/users/me?tab=authentication`

5. Нажмите кнопку **New token...**

6. Заполните форму:
   - **Name:** `Claude Code` (или любое понятное название)
   - **Scope:** выберите **YouTrack** (полный доступ к YouTrack)
   - **Expires in:** рекомендуется "No expiration" или "1 year"

7. Нажмите **Create**

8. **⚠️ ВАЖНО:** Скопируйте токен **СРАЗУ** — он показывается только один раз!

   Токен выглядит примерно так: `perm:am9obi5kb2U=.NTYtMA==.abcdefghijklmnop`

### Шаг 2: Настройка официального YouTrack Remote MCP

**Используется официальный MCP от JetBrains с HTTP transport.**

1. Найдите глобальный файл конфигурации Claude Code:

   **Windows:**
   ```
   %USERPROFILE%\.claude.json
   ```
   Пример: `C:\Users\ВашеИмя\.claude.json`

   **macOS / Linux:**
   ```
   ~/.claude.json
   ```

2. Добавьте конфигурацию официального YouTrack MCP:

```json
{
  "mcpServers": {
    "youtrack": {
      "type": "http",
      "url": "https://mag.youtrack.cloud/mcp",
      "headers": {
        "Authorization": "Bearer perm:ваш-токен-здесь"
      }
    }
  }
}
```

**Преимущества официального MCP:**
- ✅ 19 инструментов (вместо 5-6 в community MCP)
- ✅ HTTP transport (не требует Node.js/npx)
- ✅ Поддержка JetBrains
- ✅ Полный API: задачи, доски, спринты, статьи, проекты

### Шаг 3: Перезапуск Claude Code

1. Полностью закройте Claude Code (если запущен в терминале — Ctrl+C)

2. Запустите Claude Code заново:
   ```bash
   claude
   ```

3. MCP подключится автоматически через HTTP

### Шаг 4: Проверка подключения

Выполните тестовый запрос в Claude Code:

```
покажи список проектов в YouTrack
```

или

```
найди открытые задачи в проекте TS
```

Если всё настроено правильно, Claude покажет список проектов или задач.

### Доступные инструменты (19 шт.)

**Задачи:**
- `youtrack_search_issues` - поиск задач
- `youtrack_get_issue` - детали задачи
- `youtrack_update_issue` - обновление задачи
- `youtrack_find_issues_by_criteria` - поиск по критериям

**Доски и спринты:**
- `youtrack_list_boards` - список досок
- `youtrack_get_board` - детали доски
- `youtrack_find_sprints` - поиск спринтов
- `youtrack_get_sprint` - детали спринта

**Проекты:**
- `youtrack_list_projects` - список проектов
- `youtrack_find_projects_by_name` - поиск по имени

**Статьи базы знаний:**
- `youtrack_list_articles` - список статей
- `youtrack_get_article` - детали статьи
- `youtrack_get_article_attachments` - вложения
- `youtrack_get_article_comments` - комментарии
- `youtrack_get_child_articles` - дочерние статьи
- `youtrack_get_parent_article` - родительская статья

### REST API для расширенных операций

MCP не поддерживает создание/удаление проектов, досок, подсистем. Используем REST API:

```bash
# Базовый URL
https://mag.youtrack.cloud/api

# Авторизация
Authorization: Bearer perm:YOUR_TOKEN

# Примеры операций:

# Создание проекта
POST /api/admin/projects
{"name":"Название","shortName":"CODE","leader":{"id":"1-1"}}

# Создание доски
POST /api/agiles
{"name":"Название","projects":[{"id":"0-13"}]}

# Настройка столбцов доски (поле State)
POST /api/agiles/{BOARD_ID}
{"columnSettings":{"field":{"id":"113-2"}}}

# Создание подсистем (OwnedBundle)
POST /api/admin/customFieldSettings/bundles/ownedField
{"name":"Проект: Подсистемы","values":[{"name":"Sub1","description":"Описание"}]}

# Привязка подсистем к проекту
POST /api/admin/projects/{PROJECT_ID}/customFields
{"$type":"OwnedProjectCustomField","field":{"id":"113-4","$type":"CustomField"},"bundle":{"id":"BUNDLE_ID","$type":"OwnedBundle"}}

# Получение информации о доске
GET /api/agiles/{BOARD_ID}?fields=id,name,projects,columnSettings

# Список всех досок с проектами
GET /api/agiles?fields=id,name,projects(id,name,shortName)
```

**Важно:** При создании доски через API необходимо настроить `columnSettings.field` — иначе YouTrack выдаст ошибку "Не задан параметр, идентифицирующий столбцы".

### Устранение проблем

**Ошибка "Failed to connect":**
- Проверьте интернет-соединение
- Убедитесь, что URL правильный: `https://mag.youtrack.cloud/mcp`
- Токен должен начинаться с `perm:`

**Ошибка "401 Unauthorized":**
- Проверьте правильность токена (Bearer perm:...)
- Убедитесь, что токен не истёк
- URL должен заканчиваться на `/mcp`

**Токен не работает:**
- Создайте новый токен в YouTrack
- Убедитесь, что scope включает YouTrack
- Проверьте, что скопировали токен полностью
- Формат: `perm:base64.base64.random`

### Безопасность токена

- ❌ **НЕ** добавляйте токен в Git (.claude.json в .gitignore)
- ❌ **НЕ** передавайте токен другим людям
- ❌ **НЕ** публикуйте токен в чатах/форумах
- ✅ Каждый пользователь должен создать свой токен
- ✅ Используйте разные токены для разных машин
- ✅ Периодически обновляйте токены

## 2. Workflow (Статусы задач)

```
┌─────────────┐
│   Открыта   │ ← Новая задача
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ Подготовка  │ ← Анализ, уточнение требований
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  В работе   │ ← Активная разработка
└──────┬──────┘
       │
       ├──────────────┐
       ▼              ▼
┌─────────────┐ ┌─────────────┐
│   Ревью     │ │ Заблокирована│
└──────┬──────┘ └──────┬──────┘
       │               │
       ▼               │
┌─────────────┐        │
│ На проверке │ ←──────┘
└──────┬──────┘
       │
       ├──────────────┐
       ▼              ▼
┌─────────────┐ ┌─────────────┐
│   Готово    │ │  Возврат    │ → В работе
└─────────────┘ └─────────────┘
```

### Описание статусов

| Статус | Описание | Кто переводит |
|--------|----------|---------------|
| **Открыта** | Новая задача, ждёт обработки | Автоматически |
| **Подготовка** | Уточнение требований, анализ | Исполнитель |
| **В работе** | Активная разработка | Исполнитель |
| **Ревью** | Код на проверке (PR создан) | Исполнитель |
| **На проверке** | Тестирование функционала | Ревьюер |
| **Готово** | Задача выполнена | Тестировщик |
| **Заблокирована** | Ждём внешних зависимостей | Исполнитель |
| **Возврат** | Найдены проблемы | Тестировщик |

## 3. Интеграция с Git

### Формат коммитов

```
<тип>(TS-XXX): <описание на русском>

[Тело коммита - опционально]

Co-Authored-By: Claude <noreply@anthropic.com>
```

### Типы коммитов

| Тип | Описание | Пример |
|-----|----------|--------|
| `feat` | Новый функционал | `feat(TS-248): добавлен мониторинг операций` |
| `fix` | Исправление бага | `fix(TS-264): исправлено отображение карт` |
| `refactor` | Рефакторинг | `refactor(TS-230): переход на V2 API` |
| `docs` | Документация | `docs(TS-213): обновлена инструкция` |
| `style` | Стилизация | `style(TS-200): изменён фон экрана` |
| `test` | Тесты | `test(TS-235): добавлены тесты шифрования` |
| `chore` | Прочее | `chore: обновлены зависимости` |

### Связывание с задачами

**В описании PR указывать:**
```markdown
## Задача
Closes TS-248

## Изменения
- [x] Добавлен компонент мониторинга
- [x] Подключено API операций
- [x] Добавлены тесты

## Скриншоты
[Если применимо]
```

### Ветки

```
main                    # Основная ветка
├── feature/TS-248     # Новый функционал
├── fix/TS-264         # Исправление бага
├── refactor/TS-230    # Рефакторинг
└── hotfix/TS-XXX      # Срочное исправление
```

## 5. Работа с Claude Code

### Команды для работы с задачами

```bash
# Просмотр задач
"покажи открытые задачи TradeControl"
"найди задачи по терминалам"
"статус задачи TS-248"

# Работа над задачей
"работаю над TS-248"
"помоги с реализацией TS-210"

# Обновление задач
"обнови описание TS-248"
"добавь комментарий к TS-264"

# Аналитика
"покажи прогресс спринта"
"сколько задач в работе"
```

### Workflow с Claude Code

1. **Взятие задачи:**
   ```
   Ты: "беру в работу TS-248"
   Claude: [читает задачу, изучает контекст, предлагает план]
   ```

2. **Разработка:**
   ```
   Ты: "реализуй TS-248"
   Claude: [создаёт код, следует шаблонам проекта]
   ```

3. **Коммит:**
   ```
   Ты: "закоммить изменения"
   Claude: [создаёт коммит с правильным форматом и ID задачи]
   ```

4. **Завершение:**
   ```
   Ты: "задача готова"
   Claude: [предлагает обновить статус в YouTrack]
   ```

## 6. Чек-лист для задач

- [ ] Задача назначена на меня
