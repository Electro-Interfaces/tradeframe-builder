# 🌐 API Integration Guide

> ⚠️ Документ частично устарел. Для текущей схемы backend-first, переменных и авторизации используйте `docs/ARCHITECTURE_CURRENT.md`, `docs/ENVIRONMENT.md` и `docs/architecture/API_AUTHENTICATION.md`. Этот файл читать как историческую справку по интеграциям.

## Обзор системы

TradeControl Builder v1.5.16 использует гибридную систему доступа к данным с несколькими источниками.

## 🔐 Внутренняя аутентификация (PostgreSQL)

### Подключение к БД
- **PostgreSQL**: Через модуль `pg` (прямое подключение)
- **Connection string**: `DATABASE_URL` в `server/.env`
- **Схема**: `public` (основная схема БД)

### Токены
- **Формат**: `token_${base64(payload)}_${timestamp}`
- **Срок действия**: 1 час
- **Автообновление**: При 401 ошибке через сохраненные учетные данные
- **Хранение**: localStorage/sessionStorage

### Таблицы БД
- `users` - **РЕАЛЬНЫЕ пользователи системы** (не демо данные)
- `roles` - **РЕАЛЬНЫЕ роли доступа** (не демо данные)
- `user_roles` - связь пользователей с ролями (реальные данные)
- `operations` - **РЕАЛЬНЫЕ операции торговой сети** (не демо данные)
- `equipment` - **РЕАЛЬНОЕ оборудование торговых точек** (не демо данные)
- `equipment_templates` - шаблоны оборудования
- `networks` - **РЕАЛЬНЫЕ торговые сети** (не демо данные)
- `trading_points` - **РЕАЛЬНЫЕ торговые точки** (не демо данные)

## 🌐 Внешний API торговой сети (STS)

### Назначение
Получение данных по работе торговой сети и POS-системы.

### 📚 Swagger документация
- **URL**: https://pos.autooplata.ru/tms/docs
- **Описание**: Полная интерактивная документация по всем endpoints API
- **Формат**: OpenAPI 3.1.0 спецификация

### Настройка подключения
- **Конфигурация**: `src/services/apiConfigService.ts`
- **Аутентификация**: JWT (JSON Web Token) через `/v1/login`
- **Подробная документация**: См. `API_AUTHENTICATION.md`
- **Переменные окружения** (в `server/.env`):
  - `STS_API_URL` - URL API (https://pos.autooplata.ru/tms)
  - `STS_API_USERNAME` - логин для получения JWT токена
  - `STS_API_PASSWORD` - пароль для получения JWT токена

**⚠️ ВАЖНО:** Аутентификация происходит на **backend** (Node.js сервер), а не на frontend. JWT токен хранится только на backend и автоматически обновляется каждые 18 минут.

### Доступные endpoints

#### 🔄 Основные данные
- **`/v1/transactions`** - Получение списка транзакций
- **`/v2/transactions`** - Получение списка транзакций (v2 с итогами)
- **`/v1/info`** - Статусы торговых точек (ТО)
- **`/v1/tanks`** - Состояние резервуаров (текущее)
- **`/v1/tank_history`** - История по резервуарам за период (НОВЫЙ)
- **`/v1/coupons`** - Список купонов

#### 📊 Отчетность и смены (НОВЫЕ методы)
- **`/v1/shifts`** - Список смен с информацией по ПСМ (постам смены менеджера)
- **`/v1/report/receipts`** - Отчет по поступлениям нефтепродуктов (н/п)
- **`/v1/report/shift_report`** - Полный сменный отчет, включающий:
  - Информация по ПСМ (посты смены менеджера)
  - Данные по резервуарам на конец смены
  - Поступления нефтепродуктов
  - Продажи за смену
  - Движение наличных денежных средств

#### ⚙️ Конфигурация
- **`/v1/prices`** - Установка цен
- **`/v1/pos/prices/{station_number}`** - Текущие цены на торговой точке
- **`/v1/schedule/prices/{station_number}`** - Расписание цен
- **`/v1/services`** - Список услуг
- **`/v1/points`** - Список торговых точек

#### 🎛️ Управление
- **`/v1/control/restart`** - Перезагрузка терминала
- **`/v1/control/shift_open`** - Открытие смены
- **`/v1/control/shift_close`** - Закрытие смены

### Типы данных

## 🛠️ Управление подключениями

### UI Настройки
Доступ через: `/settings/external-database`

### Доступные типы подключений
1. **PostgreSQL** - основная БД (**ВСЕ основные данные РЕАЛЬНЫЕ**)
2. **External API** - API торговой сети (реальные данные)
3. **Mock** - демо данные ТОЛЬКО для вспомогательных функций
4. **Local DB** - локальная БД для разработки

> ⚠️ **КРИТИЧЕСКИ ВАЖНО**: Торговые сети, торговые точки, пользователи и роли ВСЕГДА используют реальные данные из PostgreSQL, даже в режиме разработки. Mock данные применяются только для вспомогательных функций.

### Переключение источников
Возможность динамического переключения между источниками данных через UI настроек.

## 📡 HTTP клиенты

### Основные файлы
- `src/services/httpClients.ts` - HTTP клиенты с retry логикой
- `src/services/auth/authService.ts` - аутентификация
- `src/services/apiConfigService.ts` - управление подключениями

### Особенности
- **Retry логика**: Автоповтор при ошибках
- **Idempotency-Key**: Для мутирующих операций
- **Trace-Id**: Для отслеживания запросов
- **Автоматические токены**: Добавление и обновление

## 🔒 Безопасность

### Хеширование паролей
- **Алгоритм**: SHA-256 или base64 fallback
- **Соль**: Генерируется случайно
- **Формула**: `SHA-256(password + salt)`

### Учетные данные
- **НЕ хранятся в коде** - только в переменных окружения
- **Автоматическое обновление** токенов при истечении
- **Поддержка cookies** для сессий

## 📊 Детальное описание endpoints

### `/v1/tank_history` - История по резервуарам

**Метод:** `GET`

**Описание:** Получение исторических данных о состоянии резервуаров за указанный период. Возвращает временной ряд измерений с интервалом ~10 минут.

**Параметры запроса:**

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|---------|
| `system` | integer | ✅ Да | Код системы (например, 15 для БТО) |
| `station` | integer | ✅ Да | Номер торговой точки (например, 4) |
| `dt_beg` | string | ❌ Нет | Начальная дата в формате `YYYY-MM-DD HH:MM:SS` |
| `dt_end` | string | ❌ Нет | Конечная дата в формате `YYYY-MM-DD HH:MM:SS` |

**⚠️ Формат даты:** Используйте формат `2025-10-24 00:00:00` (пробел между датой и временем), а не ISO 8601 с `T` и `Z`.

**Пример запроса:**
```bash
GET /v1/tank_history?system=15&station=4&dt_beg=2025-10-20%2000:00:00&dt_end=2025-10-24%2023:59:59
```

**Структура ответа:**

Возвращает массив объектов Tank с временными метками:

```typescript
interface TankHistoryRecord {
  number: number;           // Номер резервуара (1, 2, 3...)
  fuel: number;             // Код топлива (2=АИ-92, 3=АИ-95, 5=ДТ)
  fuel_name: string;        // Наименование топлива ("АИ-92", "АИ-95", "ДТ")
  state: number;            // Состояние резервуара (1=активен)

  // Объемные характеристики (в литрах, строки для точности)
  volume_begin: string;     // Начальный объем
  volume_end: string;       // Конечный объем
  volume_max: string;       // Максимальная вместимость
  volume_free: string;      // Свободный объем
  volume: string;           // Текущий объем

  // Массовые характеристики (в килограммах)
  amount_begin: string;     // Начальная масса
  amount_end: string;       // Конечная масса

  // Физические параметры
  level: string;            // Уровень в см
  temperature: string;      // Температура в °C
  density: string;          // Плотность в кг/м³

  // Данные о воде
  water: {
    volume: string;         // Объем воды в литрах
    amount: string;         // Масса воды в кг
    level: string;          // Уровень воды в см
  };

  // Реализация (отпуск топлива)
  release: {
    volume: string;         // Объем отпущенного топлива в литрах
    amount: string;         // Масса отпущенного топлива в кг
  };

  dt: string;               // Дата и время измерения (ISO 8601)
}
```

**Пример ответа:**
```json
[
  {
    "number": 1,
    "fuel": 5,
    "fuel_name": "ДТ",
    "state": 1,
    "volume_begin": "8980.360",
    "volume_end": "8980.360",
    "volume_max": "10129.880",
    "volume_free": "1254.880",
    "volume": "8875.000",
    "amount_begin": "7445.780",
    "amount_end": "7445.780",
    "level": "171.410",
    "water": {
      "volume": "0.000",
      "amount": "0.000",
      "level": "0.000"
    },
    "temperature": "6.300",
    "density": "832.980",
    "release": {
      "volume": "291.320",
      "amount": "242.660"
    },
    "dt": "2025-10-24T15:37:08"
  }
]
```

**Особенности использования:**

1. **Частота данных**: Измерения поступают примерно каждые 10 минут
2. **Числовые строки**: Все числовые значения возвращаются как строки для сохранения точности
3. **Множественные резервуары**: Ответ включает данные по всем резервуарам станции
4. **Временной ряд**: Для построения графиков используйте поле `dt` как временную ось
5. **Реализация топлива**: Поле `release` показывает накопленный отпуск топлива с начала периода

**Типичные сценарии использования:**

- 📈 Построение графиков изменения уровня топлива
- 📊 Анализ динамики продаж по резервуарам
- 🔍 Выявление утечек или аномалий в объеме
- 📉 Мониторинг температуры и плотности топлива
- 💧 Контроль уровня воды в резервуарах

**Backend Proxy:**
Запросы проходят через backend proxy `http://localhost:3001/api/sts/v1/tank_history` с автоматической JWT авторизацией.
